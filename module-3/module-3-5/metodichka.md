# 3.5. Нормализация данных. Форматирование данных

**Цель:** привести грязные поля логов пользователей к общим правилам: текст без лишних пробелов, секунды и время в одном виде, канал в одном словаре, длительность ещё и на шкале от 0 до 1.

**Опора:** PostgreSQL из раздела 3.1, пакеты `pandas`, `sqlalchemy`, `psycopg` из раздела 3.4. Ядро Jupyter — `./.venv/Scripts/python.exe`. Рабочая папка VS Code — корень курса.

**Итоговые артефакты** (в папке `module-3-5/`):

| Файл | Назначение |
|------|------------|
| `sql/user_logs_dirty.sql` | Логи с разным регистром, запятой в секундах и тремя шаблонами времени |
| `lab35-format.ipynb` | Приведение полей и запись результата |
| таблица `user_logs_ready` | Логи после форматирования и нормировки длительности |

Форматирование меняет запись значения, но не его смысл: `"  400,5 "` и `400.5` — одна длительность. Нормировка переводит секунды на общую шкалу. Исходные секунды при этом не стирают.

## 3.5.1. Чтение строками

```python
import pandas as pd
import sqlalchemy as sa

engine = sa.create_engine(
    "postgresql+psycopg://student:student@localhost:5432/course"
)
raw = pd.read_sql(
    sa.text("SELECT * FROM user_logs_dirty ORDER BY log_id"),
    engine,
)
frame = raw.astype(str)
print(frame.dtypes)
print(frame)
```

Чтение строками не даёт pandas угадать число или дату до ваших правил.

**Критерий 3.5.1:** четыре строки, все столбцы текстовые, кириллица читается.

## 3.5.2. Текст и канал

```python
frame["city"] = frame["city"].str.strip().str.lower()
frame["channel"] = frame["channel"].str.strip().str.lower()
print(frame["city"].tolist())
print(frame["channel"].unique().tolist())
```

**Практика 3.5.2.** Замените канал словарём: `поиск` → `search`, `реклама` → `ads`, `письмо` → `email`. Неизвестное значение оставьте как есть.

```python
channel_map = {"поиск": "search", "реклама": "ads", "письмо": "email"}
frame["channel"] = frame["channel"].map(channel_map).fillna(frame["channel"])
print(frame["channel"].tolist())
```

**Критерий 3.5.2:** города — `москва`, `казань`, `москва`, `тула`. Каналы — `search`, `ads`, `search`, `email`.

## 3.5.3. Секунды как число

Пробел отделяет тысячи, запятая — дробную часть. Перед числом пробелы убирают, запятую меняют на точку.

```python
frame["seconds"] = (
    frame["seconds"]
    .str.replace(" ", "", regex=False)
    .str.replace(",", ".", regex=False)
    .astype(float)
)
print(frame["seconds"].tolist())
print(frame["seconds"].sum())
```

**Критерий 3.5.3:** значения `1200.5`, `980.0`, `2450.0`, `1500.0`. Сумма равна **6130.5**.

---

## 3.5.4. Время события

В `12.03.2026` и `13/03/2026` день стоит первым. `format="mixed"` разбирает несколько шаблонов, `dayfirst=True` не даёт перепутать день и месяц.

```python
frame["logged_at"] = pd.to_datetime(
    frame["logged_at"],
    format="mixed",
    dayfirst=True,
)
frame["logged_at"] = frame["logged_at"].dt.strftime("%Y-%m-%d")
print(frame["logged_at"].tolist())
```

**Критерий 3.5.4:** даты равны `2026-03-12`, `2026-03-13`, `2026-03-13`, `2026-03-14`.

## 3.5.5. Общая шкала длительности

Минимакс переводит секунды в отрезок от 0 до 1. Исходный столбец остаётся: по нему сверяют сумму и строят ось в секундах. Норма нужна, когда длительность сравнивают с признаком в других единицах.

```python
low = frame["seconds"].min()
high = frame["seconds"].max()
frame["seconds_norm"] = (frame["seconds"] - low) / (high - low)
print(frame[["seconds", "seconds_norm"]])
```

Минимум `980` получает 0, максимум `2450` получает 1.

**Практика 3.5.5.** Посчитайте норму для `1500`: `(1500 - 980) / (2450 - 980)`. Сверьте с ячейкой.

**Критерий 3.5.5:** в `seconds_norm` есть 0 и 1. Для `1500` норма примерно **0.3537**. Столбец `seconds` на месте.

## 3.5.6. Запись в базу

```python
ready = frame[
    ["log_id", "user_name", "city", "seconds", "seconds_norm", "logged_at", "channel"]
]
ready.to_sql("user_logs_ready", engine, if_exists="replace", index=False)

check = pd.read_sql(
    sa.text("SELECT * FROM user_logs_ready ORDER BY log_id"),
    engine,
)
print(check)
print("сумма", check["seconds"].sum())
```

**Критерий 3.5.6:** в `user_logs_ready` четыре строки, сумма секунд **6130.5**, даты вида `2026-03-12`, каналы `search`, `ads`, `email`. Таблица видна в DBeaver.

### Типовые ошибки

| Симптом | Что проверить |
|---------|----------------|
| Секунды стали `1200` без дроби или `NaN` | Сначала удаляют пробелы, потом запятую меняют на точку |
| `Москва` и `МОСКВА` остались разными | Нет `strip` или `lower` |
| Дата `12.03.2026` стала 3 декабря | В `to_datetime` не передан `dayfirst=True` |
| Деление на ноль в норме | В столбце одно и то же число: минимум равен максимуму |
| В базе снова текст с запятой | В `to_sql` уходит `frame` после `astype(float)`, а не исходный `raw` |
| Нет соединения | Контейнер запущен, строка подключения — `student` и база `course` |

После занятия одна строка — одна сессия, секунды и даты сравнимы, каналы названы одинаково. Модуль 4 забирает из `user_logs_ready` массивы секунд, нормы и времени, модуль 6 — норму и канал как признаки, длительность как ответ.
