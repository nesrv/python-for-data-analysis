2.7 Профилирование кода

Объём занятия: 2 академических часа (~120 минут) активной практики в Visual Studio Code.

Цель: измерить, какая функция занимает время, и сравнить два способа одного и того же подсчёта. Профиль не ищет логическую ошибку: для неё нужен отладчик из раздела 2.6.

Опора: терминал VS Code с активированным .venv. Рабочая папка — корень курса.

Итоговые артефакты (в папке module-2-7/):

Файл Назначение
profile_demo.py Две реализации суммы, которые сравнивают
profile.txt Сохранённый вывод cProfile
lab27-profile.ipynb Замеры timeit и короткий вывод

Подготовка

Создайте ноутбук module-2-7/lab27-profile.ipynb, ядро — .venv. Первая ячейка — markdown: ФИО, дата, заголовок «2.7 Профилирование кода».

2.7.1. Зачем профиль

Время программы складывается из времени функций. cProfile считает, сколько раз функция вызвана и сколько времени на неё пришлось. Сначала смотрят функции с большим накопленным временем, затем решают, есть ли более простой алгоритм.

Профиль запускают на той же задаче, которую программа решает у пользователя. Замер на пустом списке ничего не говорит о рабочем объёме данных.

Критерий 2.7.1: в markdown одной фразой записано, чем профиль отличается от точки останова.

2.7.2. cProfile

Создайте module-2-7/profile_demo.py:

def slow_sum(n: int) -> int:
    total = 0
    for i in range(n):
        total += i
    return total


def fast_sum(n: int) -> int:
    return n * (n - 1) // 2


def main():
    left = slow_sum(200_000)
    right = slow_sum(100_000)
    return left + right


if __name__ == "__main__":
    print(main())

Из корня курса, в активированном .venv:

python -m cProfile -s cumtime module-2-7\profile_demo.py

-s cumtime сортирует таблицу по накопленному времени: сверху функции, внутри которых программа провела больше всего времени, вместе с вызовами из них.

Сохраните вывод:

python -m cProfile -s cumtime module-2-7\profile_demo.py > module-2-7\profile.txt

В таблице найдите строку slow_sum. Колонка ncalls — число вызовов.

Практика 2.7.2. В ноутбуке запишите: сколько раз вызвана slow_sum, какое число напечатал скрипт, какая функция стоит в таблице выше неё.

Число на выходе — сумма 0..199999 плюс сумма 0..99999, то есть 199999 * 200000 / 2 + 99999 * 100000 / 2. Скрипт печатает 24999850000.

Критерий 2.7.2: в profile.txt у slow_sum два вызова, скрипт печатает 24999850000.

2.7.3. Сравнение двух реализаций

Замените тело main, чтобы обе функции считали одну и ту же величину:

def main():
    a = slow_sum(300_000)
    b = fast_sum(300_000)
    print("совпали:", a == b)
    return a

Снова сохраните профиль в profile.txt. Сравните tottime у slow_sum и fast_sum. tottime — время в самой функции, без учёта других вызовов. У формулы оно заметно меньше, чем у цикла.

Практика 2.7.3. В markdown перепишите две строки профиля: имя, ncalls, tottime. Отметьте, какая реализация быстрее на этом запуске.

Критерий 2.7.3: скрипт печатает совпали: True. У slow_sum время в tottime больше, чем у fast_sum.

2.7.4. timeit

timeit повторяет один маленький фрагмент много раз и возвращает суммарные секунды. Так сравнивают короткие выражения, не запуская полный профиль.

Ячейка:

import timeit

loop = timeit.timeit("sum(range(10_000))", number=500)
formula = timeit.timeit("n * (n - 1) // 2", number=500, setup="n = 10_000")
print("sum(range):", loop)
print("формула:", formula)
print("цикл медленнее в", round(loop / formula, 1), "раз")

Числа от запуска к запуску немного меняются. Вывод «формула быстрее» должен сохраняться.

Практика 2.7.4. Повторите замер с number=100 и с number=500. В markdown запишите оба отношения. Не сравнивайте абсолютные секунды разных компьютеров между собой.

Критерий 2.7.4: в обоих замерах формула занимает меньше времени, чем sum(range(...)).

2.7.5. Что не ускоряют вслепую

Ускорение имеет смысл там, где профиль показал заметную долю времени. Функция, которая вызвана один раз и занимает доли процента, не стоит переписывания на этом занятии.

Практика 2.7.5. В profile.txt после раздела 2.7.3 найдите строку, у которой tottime меньше, чем у slow_sum. Запишите её имя и одну фразу: почему её не переписывают первой.

Критерий 2.7.5: в заметке названа функция с меньшим tottime, чем у slow_sum, и сказано, что сначала меняют самую дорогую часть.

2.7.6. Самопроверка

В конце ноутбука ответьте:

  1. Чем ncalls отличается от tottime.
  2. Зачем один и тот же подсчёт записан циклом и формулой.
  3. Почему один запуск timeit с number=1 плохо сравнивает короткие выражения.

Типовые ошибки

Симптом Что проверить
profile.txt пустой или в неожиданной кодировке Перенаправление сделано из PowerShell в корне курса; откройте файл в VS Code как UTF-8
В таблице нет slow_sum Запущен не module-2-7\profile_demo.py
совпали: False Формула считает сумму 0 .. n-1, как и цикл range(n)
