2.1.1. Изменяемые и неизменяемые типы

Неизменяемый объект нельзя поменять «на месте»: операция создаёт новое значение. Изменяемый объект можно дополнить или перезаписать, и все имена, которые на него ссылаются, увидят это изменение.

Неизменяемые: int, float, bool, str, tuple, frozenset, None.

Изменяемые: list, dict, set и большинство объектов своих классов.

Ячейка — неизменяемое число и строка:

n = 10
print("id до", id(n))
n = n + 1
print("n =", n, "id после", id(n))

s = "py"
print("строка до", id(s))
s = s + "thon"
print("строка", s, "id после", id(s))

Имя n после сложения указывает на другой объект. Исходное число 10 не изменилось.

Ячейка — изменяемый список:

items = ["a"]
print("id списка", id(items))
items.append("b")
items[0] = "A"
print(items, "id тот же", id(items))

append и запись по индексу меняют тот же список: id не меняется.

Ячейка — кортеж с изменяемым элементом:

pair = (1, ["x"])
# pair[0] = 2          # TypeError: кортеж неизменяем
pair[1].append("y")    # список внутри кортежа изменяем
print(pair)

Неизменяемость кортежа запрещает заменить элемент. Она не замораживает объекты, которые уже лежат внутри.

Ячейка — что можно использовать как ключ:

catalog = {("Анна", 1): 18, "Борис": 15}
print(catalog[("Анна", 1)])
# catalog[["Вера"]] = 20  # TypeError: список нельзя сделать ключом

Ключ словаря должен быть неизменяемым.

Практика 2.1.1. Для каждого значения запишите в markdown «изменяемое» или «неизменяемое»: 3.14, "текст", [1, 2], (1, 2), {"a": 1}, {1, 2}, True.

Критерий 2.1.1: у числа и строки id после переприсваивания другой; у списка после append id тот же; кортеж с вложенным списком печатает (1, ['x', 'y']); практика заполнена.

2.1.6. Свой тип: класс

Объекты пользовательского класса устроены так же: экземпляр, тип, атрибуты, методы.

Файл module-2-1/objects_demo.py:

class Score:
    def __init__(self, name: str, points: int):
        self.name = name
        self.points = points

    def passed(self) -> bool:
        return self.points >= 12

    def __repr__(self) -> str:
        return f"Score({self.name!r}, {self.points})"


def main():
    group = [Score("Анна", 18), Score("Борис", 9), Score("Вера", 12)]
    print(type(group[0]).__name__)
    print(isinstance(group[0], Score))
    passed = [item for item in group if item.passed()]
    print(passed)


if __name__ == "__main__":
    main()

2.2.1. Модуль и инструкция import

Модуль — файл с кодом Python. Пакет — папка с модулями и файлом __init__.py. Инструкция import выполняет модуль (при первом обращении) и связывает имя в текущем пространстве имён с объектом модуля.

Ячейка:

import math

print(type(math).__name__, math.__name__)
print("файл:", math.__file__)
print("pi =", round(math.pi, 5))

Имя math указывает на модуль. Функция sqrt доступна как атрибут: math.sqrt. Сама по себе она в ноутбук не попадает.

Ячейка — имя не появляется само:

try:
    print(sqrt(16))
except NameError as error:
    print(type(error).__name__, error)

Критерий 2.2.1: напечатаны тип module, путь к math внутри установки Python и текст NameError.

2.2.2. Формы импорта

Ячейка — модуль целиком и псевдоним:

import statistics as stats
from pathlib import Path

print(stats.mean([2, 4, 4, 4, 5, 5, 7, 9]))
print(Path.cwd().name)

Ячейка — одно имя из модуля:

from math import sqrt

print(sqrt(16))

После from math import sqrt в пространстве имён ячейки есть имя sqrt. Имени math эта строка не создаёт.

**Ячейка — почему не используют import *:**

from math import pi as math_pi

pi = 3
print("локальное pi =", pi)
print("math.pi =", math_pi)

from math import * занёс бы в текущее пространство имён десятки имён и мог бы затереть уже занятое pi. В курсе так не пишем: импортируйте модуль или перечисляйте нужные имена.

Практика 2.2.2. Импортируйте median из statistics под именем med и посчитайте медиану списка [9, 1, 4].

Критерий 2.2.2: в ноутбуке есть import …, import … as … и from … import …; медиана равна 4.

2.2.3. Пространства имён

Пространство имён — соответствие имени и объекта. У модуля, функции и ячейки ноутбука оно своё. Поиск имени идёт от локального пространства наружу: функция, затем модуль, затем встроенные имена (len, print, int).

Ячейка:

label = "модуль"

def show():
    label = "функция"
    print("внутри:", label)

show()
print("снаружи:", label)
print("встроенное:", len([1, 2, 3]))

Присваивание label = "функция" создаёт локальное имя. Внешнее label не меняется.

Ячейка — чтение внешнего имени:

factor = 10

def scale(value):
    return value * factor

print(scale(3))

Если внутри функции нет присваивания в factor, Python читает имя снаружи.

Ячейка — что сейчас в пространстве имён:

import math
names = [name for name in dir() if not name.startswith("_")]
print(sorted(names))

Практика 2.2.3. Напишите функцию title(), внутри которой переменная label = "внутри". Снаружи до вызова задайте label = "снаружи". Напечатайте оба значения и одной фразой в markdown объясните, почему они разные.

Критерий 2.2.3: вызов печатает внутри, затем снаружи остаётся снаружи; scale(3) равно 30.

2.2.7. Имя __name__

У модуля есть имя. Если файл запущен как программа, Python задаёт __name__ равным "__main__". Если файл импортирован, __name__ равен имени модуля. Так отделяют код, который должен выполниться только при запуске файла.

В конец module-2-2/run_grades.py добавьте:

if __name__ == "__main__":
    print("запуск как программа")

Вызов from course_tools.grades import passed при импорте модуля эту строку не печатает: она относится к run_grades.py, а не к пакету. Проверьте оба способа:

python -c "import run_grades"

Вторую команду выполняйте из каталога module-2-2. При импорте строка «запуск как программа» не появляется, если весь сценарий с баллами тоже стоит под if __name__ == "__main__". Перенесите цикл по scores внутрь этой ветки.

Критерий 2.2.7: прямой запуск печатает баллы и «запуск как программа»; import run_grades завершается без этой строки.

2.2.8. Ленивый импорт (Python 3.15)

Обычный import сразу ищет модуль, компилирует его и выполняет код верхнего уровня. В Python 3.15 тот же импорт можно отложить мягким ключевым словом lazy (PEP 810):

lazy import json
lazy from pathlib import Path

На строке lazy import модуль не загружается. Интерпретатор связывает имя с лёгким посредником. Загрузка происходит при первом использовании этого имени: json.loads(...) или обращение к Path. Слово lazy — мягкое ключевое слово: оно особое только перед import и from. Переменную по-прежнему можно назвать lazy.

Проверка версии:

python --version

Дальнейшие ячейки выполняйте, если версия 3.15 или новее. На 3.12 и 3.13 строка lazy import даёт SyntaxError. В этом случае раздел читают и в markdown записывают фактическую версию: код занятия на этой версии не запускается.

Ячейка — модуль ещё не в sys.modules:

import sys

lazy import json

print("до обращения:", "json" in sys.modules)
text = json.dumps({"hello": "world"})
print(text)
print("после обращения:", "json" in sys.modules)

До вызова dumps ключа json в sys.modules нет. После вызова модуль загружен.

Ячейка — lazy from:

import sys

lazy from json import dumps, loads

print("до обращения:", "json" in sys.modules)
print(dumps({"a": 1}))
print("после dumps:", "json" in sys.modules)

Первое обращение к любому из имён (dumps или loads) загружает весь модуль json. В объект превращается то имя, к которому обратились. Второе имя остаётся ленивым, пока его не используют.

Ошибка «модуля нет» возникает не на строке импорта, а в месте первого использования. В трассировке видны обе точки: обращение к имени и исходная строка lazy import.

lazy допустим только на уровне модуля. Такие варианты — синтаксическая ошибка:

def load():
    lazy import json          # нельзя внутри функции

class Box:
    lazy import json          # нельзя в теле класса

try:
    lazy import json          # нельзя в try
except ImportError:
    pass

lazy from json import *      # нельзя вместе со звёздочкой
lazy from __future__ import annotations

Импорт внутри функции по-прежнему возможен обычным import без lazy: он выполнится в момент вызова функции. Это другой приём, он был и до 3.15.

Глобальный режим без правки каждого файла: запуск python -X lazy_imports=all или переменная среды PYTHON_LAZY_IMPORTS=all. Значение normal (оно и есть значение по умолчанию) ленивыми делает только импорты со словом lazy. Режим можно запросить из кода: sys.set_lazy_imports("all") и прочитать sys.get_lazy_imports(). Фильтр sys.set_lazy_imports_filter(...) решает, какие модули в режиме all остаются ленивыми.

Практика 2.2.8. На Python 3.15 добавьте в отдельный файл module-2-2/lazy_demo.py две строки: lazy import statistics и печать statistics.mean([1, 2, 3]). Запустите файл. В markdown напишите, в какой момент модуль statistics попадает в sys.modules. На более старой версии ограничьтесь записью python --version и пометкой «синтаксис недоступен».

2.3.1. Путь к файлу

Файл на диске адресуют путём. pathlib.Path собирает путь из частей, создаёт папки и не зависит от того, какой в системе разделитель каталогов.

Ячейка:

from pathlib import Path

data_dir = Path("module-2-3") / "data"
data_dir.mkdir(parents=True, exist_ok=True)

notes = data_dir / "notes.txt"
print("каталог:", data_dir.resolve())
print("файл:", notes)
print("существует:", notes.exists())
print("родитель:", notes.parent.name, "имя:", notes.name, "суффикс:", notes.suffix)

mkdir(..., exist_ok=True) не падает, если папка уже есть. parents=True создаёт и промежуточные каталоги.

2.3.2. Текст: запись и чтение

Текст в курсе пишут и читают в кодировке UTF-8. Так кириллица одинаково открывается в VS Code и в Python.

Ячейка — запись целиком:

notes.write_text("Анна: 18\nБорис: 15\nВера: 20\n", encoding="utf-8")
print(notes.read_text(encoding="utf-8"))

write_text создаёт файл или полностью заменяет его содержимое.

Ячейка — по строкам:

lines = notes.read_text(encoding="utf-8").splitlines()
print(len(lines), lines[0])

splitlines() убирает символы перевода строки. Пустая строка в конце файла отдельным элементом не становится, если после последней строки ничего нет.

2.3.3. Режим открытия и with

open возвращает файловый объект. Его нужно закрыть: иначе буфер может не дописаться на диск. Конструкция with закрывает файл и при обычном выходе, и при исключении.

РежимДействие
"r"Чтение. Файл должен существовать
"w"Запись с нуля. Содержимое стирается
"a"Дозапись в конец
"x"Создание только нового файла. Если файл есть — ошибка

Для текста к режиму добавляют кодировку: encoding="utf-8".

Ячейка:

log_path = data_dir / "log.txt"
with log_path.open("w", encoding="utf-8") as file:
    file.write("старт\n")

with log_path.open("a", encoding="utf-8") as file:
    file.write("ещё строка\n")

with log_path.open("r", encoding="utf-8") as file:
    print(file.read())

Ячейка — файл уже есть:

try:
    with log_path.open("x", encoding="utf-8") as file:
        file.write("не запишется\n")
except FileExistsError as error:
    print(type(error).__name__)

Критерий 2.3.3: в log.txt две строки, open("x") по существующему файлу даёт FileExistsError.

2.3.4. CSV

CSV — текст, в котором поля разделены запятой, а первая строка часто содержит имена столбцов. Модуль csv учитывает кавычки и перевод строки внутри поля. В Windows при записи передают newline="", иначе между строками появляется лишняя пустая строка.

Ячейка — запись:

import csv

table = data_dir / "notes.csv"
rows = [
    {"name": "Анна", "score": 18},
    {"name": "Борис", "score": 15},
    {"name": "Вера", "score": 20},
    {"name": "Глеб", "score": 11},
]
with table.open("w", encoding="utf-8", newline="") as file:
    writer = csv.DictWriter(file, fieldnames=["name", "score"])
    writer.writeheader()
    writer.writerows(rows)
print(table.read_text(encoding="utf-8"))

Ячейка — чтение и сводка:

with table.open(encoding="utf-8", newline="") as file:
    loaded = list(csv.DictReader(file))

scores = [int(row["score"]) for row in loaded]
lines = [
    f"записей: {len(loaded)}",
    f"сумма баллов: {sum(scores)}",
    f"максимум: {max(scores)}",
]
summary = data_dir / "summary.txt"
summary.write_text("\n".join(lines) + "\n", encoding="utf-8")
print(summary.read_text(encoding="utf-8"))

DictReader отдаёт каждую строку словарём. Числа из CSV приходят строками, поэтому балл переводят через int.

Практика 2.3.4. Допишите в сводку строку сдавших: N, где N — число баллов >= 12.

Критерий 2.3.4: сумма баллов 64, максимум 20, сдавших 3.

2.3.5. JSON

JSON хранит списки, словари, числа, строки и логические значения. Его удобно читать целиком: json.loads / json.dumps или json.load / json.dump для файла. Ключи JSON — строки.

Ячейка:

import json

payload = {"course": "2.3", "students": rows}
json_path = data_dir / "group.json"
json_path.write_text(
    json.dumps(payload, ensure_ascii=False, indent=2),
    encoding="utf-8",
)
restored = json.loads(json_path.read_text(encoding="utf-8"))
print(restored["course"], len(restored["students"]))
print(restored["students"][0]["score"], type(restored["students"][0]["score"]))

ensure_ascii=False оставляет кириллицу символами, а не последовательностями \u..... indent=2 делает файл читаемым в редакторе.

Число в JSON после чтения снова имеет тип int, в отличие от CSV.

Практика 2.3.5. Запишите тот же словарь через json.dump в файл module-2-3/data/group-dump.json и прочитайте его через json.load. Сравните два словаря оператором ==.

dump_path = data_dir / "group-dump.json"
with dump_path.open("w", encoding="utf-8") as file:
    json.dump(payload, file, ensure_ascii=False, indent=2)
with dump_path.open(encoding="utf-8") as file:
    from_dump = json.load(file)
print(from_dump == restored)

Критерий 2.3.5: сравнение даёт True, в файле видны имена кириллицей.

2.3.6. Ошибки чтения

Ячейка — нет файла:

missing = data_dir / "missing.txt"
try:
    missing.read_text(encoding="utf-8")
except FileNotFoundError as error:
    print(type(error).__name__, error.filename)

Ячейка — неверная кодировка. Файл notes.txt записан в UTF-8. Чтение как cp1251 может не упасть, но текст будет другим, либо дать UnicodeDecodeError на байтах, которых в этой кодировке нет. Проверьте оба исхода так:

raw = notes.read_bytes()
print("первые байты:", raw[:12])
print("как utf-8:", raw.decode("utf-8").splitlines()[0])

Байты файла и строка — разные объекты. read_bytes не применяет кодировку. Для текста курса используйте UTF-8 и в Python, и в статусной строке VS Code (справа внизу при открытии файла).

Практика 2.3.6. Откройте notes.csv в VS Code и убедитесь, что кодировка UTF-8. Если редактор предлагает другую, переключите её и пересохраните файл только если текст уже отображается верно.

Критерий 2.3.6: отсутствующий файл даёт FileNotFoundError; первая строка, прочитанная из байтов как UTF-8, равна Анна: 18.
