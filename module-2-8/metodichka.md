## 2.8.1. Класс Point

Класс описывает устройство объекта. Экземпляр хранит свои `x` и `y`. Метод экземпляра получает этот объект первым аргументом `self`.

```python
class Point:
    def __init__(self, x: float, y: float) -> None:
        self.x = x
        self.y = y

    def move(self, dx: float, dy: float) -> None:
        self.x += dx
        self.y += dy


a = Point(2, 3)
a.move(1, -1)
print(a.x, a.y)
print(type(a).__name__)
```

`Point(2, 3)` вызывает `__init__`. `a.move(1, -1)` сдвигает только эту точку.

**Практика 2.8.1.** Добавьте метод `copy`, который возвращает новый `Point` с теми же координатами. Сдвиньте копию и убедитесь, что исходная точка не изменилась.

**Критерий 2.8.1:** после `move` у `a` координаты `3` и `2`. Копия после своего сдвига не меняет `a`.

## 2.8.2. Метод класса и статический метод

Метод экземпляра работает с одной точкой. Метод класса получает сам класс аргументом `cls` и обычно создаёт экземпляр. Статический метод не получает ни точку, ни класс: это функция, которая логически живёт рядом с классом.

```python
class Point:
    def __init__(self, x: float, y: float) -> None:
        self.x = x
        self.y = y

    @classmethod
    def origin(cls) -> "Point":
        return cls(0, 0)

    @staticmethod
    def same_place(left: "Point", right: "Point") -> bool:
        return left.x == right.x and left.y == right.y


start = Point.origin()
other = Point(0, 0)
print(start.x, start.y, Point.same_place(start, other))
```

`Point.origin()` вызывает `origin` от класса. Внутри `cls` — это `Point`, поэтому `cls(0, 0)` создаёт точку.

**Практика 2.8.2.** Добавьте метод класса `from_pair(cls, pair)`, который принимает кортеж `(x, y)` и возвращает точку. Проверьте на `(4, 5)`.

**Критерий 2.8.2:** `Point.origin()` даёт координаты `0` и `0`, `same_place` для двух таких точек возвращает `True`, `from_pair((4, 5))` даёт точку с этими координатами.

## 2.8.3. Служебные методы

Имена с двумя подчёркиваниями с обеих сторон Python вызывает сам: при печати, сравнении и сложении. Их задача — чтобы объект вёл себя как значение, а не только как набор полей.

```python
class Point:
    def __init__(self, x: float, y: float) -> None:
        self.x = x
        self.y = y

    def __repr__(self) -> str:
        return f"Point({self.x}, {self.y})"

    def __eq__(self, other: object) -> bool:
        if not isinstance(other, Point):
            return NotImplemented
        return self.x == other.x and self.y == other.y

    def __add__(self, other: "Point") -> "Point":
        return Point(self.x + other.x, self.y + other.y)


a = Point(1, 2)
b = Point(1, 2)
c = a + Point(3, 4)
print(a, a == b, c)
```

`__repr__` даёт строку, по которой видно координаты. `__eq__` сравнивает координаты, а не идентичность объекта. `__add__` не меняет слагаемые и возвращает новую точку.

**Практика 2.8.3.** Добавьте `__sub__`: разность двух точек — новая точка. Проверьте `Point(5, 4) - Point(1, 1)`.

**Критерий 2.8.3:** печать показывает `Point(1, 2)`, две разные точки с одними координатами равны, сумма равна `Point(4, 6)`, разность равна `Point(4, 3)`.

## 2.8.4. __slots__

Обычный экземпляр хранит атрибуты в словаре `__dict__`. В `__slots__` перечисляют допустимые имена: лишнее поле создать нельзя, словарь на каждый экземпляр не заводится.

```python
class SlotPoint:
    __slots__ = ("x", "y")

    def __init__(self, x: float, y: float) -> None:
        self.x = x
        self.y = y


p = SlotPoint(1, 2)
print(p.x, p.y)
print(hasattr(p, "__dict__"))
```

Попытка `p.label = "A"` заканчивается `AttributeError`: имени `label` нет в `__slots__`.

**Практика 2.8.4.** В отдельной ячейке поймайте эту ошибку через `try` / `except AttributeError` и напечатайте `"поле не предусмотрено"`.

**Критерий 2.8.4:** `hasattr(p, "__dict__")` даёт `False`. Непредусмотренное поле не создаётся, ячейка с `except` печатает «поле не предусмотрено».

## 2.8.5. Dataclass

Для класса, который в основном хранит поля, декоратор `dataclass` сам пишет `__init__`, `__repr__` и `__eq__`. Свои методы добавляют как обычно. Параметр `slots=True` включает ограничение имён из раздела 2.8.4.

```python
from dataclasses import dataclass


@dataclass(slots=True)
class Point:
    x: float
    y: float

    def move(self, dx: float, dy: float) -> None:
        self.x += dx
        self.y += dy


a = Point(2, 3)
b = Point(2, 3)
a.move(1, 0)
print(a, a == b)
```

Поля объявлены в теле класса. `Point(2, 3)` работает без рукописного `__init__`. После `move` точки уже не равны.

**Практика 2.8.5.** Добавьте поле `label: str = ""`. Создайте `Point(1, 1)` без подписи и `Point(1, 1, "старт")`. Напечатайте оба объекта.

**Критерий 2.8.5:** после сдвига печать показывает `Point(3, 3)`, сравнение с исходной копией даёт `False`. Точка без подписи имеет пустую строку в `label`.

## 2.8.6. Наследование

Подкласс забирает методы базового класса и добавляет своё. `super()` вызывает версию базового класса, чтобы не копировать её тело.

Вернитесь к рукописному `Point` с `__init__`, `__repr__` и `move` из разделов 2.8.1 и 2.8.3. Dataclass в этой ячейке не используйте: у него другой способ объявления полей.

```python
class Point3D(Point):
    def __init__(self, x: float, y: float, z: float) -> None:
        super().__init__(x, y)
        self.z = z

    def __repr__(self) -> str:
        return f"Point3D({self.x}, {self.y}, {self.z})"

    def lift(self, dz: float) -> None:
        self.z += dz


p = Point3D(1, 2, 3)
p.move(1, 1)
p.lift(4)
print(p, isinstance(p, Point))
```

`move` не написан в `Point3D`: он пришёл из `Point`. `isinstance(p, Point)` истинен, потому что трёхмерная точка остаётся точкой.

**Практика 2.8.6.** Добавьте в `Point3D` метод `__add__`, который складывает и `z`. Проверьте `Point3D(1, 1, 1) + Point3D(2, 3, 4)`.

**Критерий 2.8.6:** после `move` и `lift` объект печатается как `Point3D(2, 3, 7)`. Сумма равна `Point3D(3, 4, 5)`. `isinstance` относительно `Point` истинен.

## 2.8.7. Полиморфизм

Полиморфизм здесь — один и тот же вызов метода у объектов разных классов. Цикл не проверяет тип: у каждого объекта есть свой `place`.

```python
class Marker:
    def place(self) -> str:
        raise NotImplementedError


class Point(Marker):
    def __init__(self, x: float, y: float) -> None:
        self.x = x
        self.y = y

    def place(self) -> str:
        return f"точка ({self.x}, {self.y})"


class Circle(Marker):
    def __init__(self, x: float, y: float, radius: float) -> None:
        self.x = x
        self.y = y
        self.radius = radius

    def place(self) -> str:
        return f"круг ({self.x}, {self.y}) r={self.radius}"


def describe(items: list[Marker]) -> None:
    for item in items:
        print(item.place())


describe([Point(1, 2), Circle(0, 0, 5)])
```

`describe` вызывает `place`. Какой текст вернётся, решает класс конкретного объекта.

**Практика 2.8.7.** Добавьте класс `Label` с методом `place`, который возвращает текст подписи. Передайте его в тот же `describe` третьим элементом.

**Критерий 2.8.7:** в выводе есть строка про точку, строка про круг и строка подписи. В `describe` нет проверки `isinstance`.

## 2.8.8. Миксин

Миксин — небольшой класс с одним дополнительным поведением. Его не создают сам по себе: подмешивают в класс слева в списке базовых классов.

```python
class LabelMixin:
    label: str

    def tagged(self) -> str:
        return f"[{self.label}] {self.place()}"


class NamedPoint(LabelMixin, Point):
    def __init__(self, x: float, y: float, label: str) -> None:
        super().__init__(x, y)
        self.label = label


item = NamedPoint(2, 3, "старт")
print(item.place())
print(item.tagged())
```

`NamedPoint` берёт `place` у `Point` и `tagged` у `LabelMixin`. Порядок записи `LabelMixin, Point` важен: Python ищет метод слева направо.

**Практика 2.8.8.** Сделайте `NamedCircle(LabelMixin, Circle)` и напечатайте `tagged()` для круга с подписью `"зона"`.

**Критерий 2.8.8:** у именованной точки `tagged()` содержит `[старт]` и текст `place`. У именованного круга в строке есть `[зона]` и радиус.

### Типовые ошибки

| Симптом | Что проверить |
|---------|----------------|
| `TypeError: move() missing 1 required positional argument` | Метод вызван от класса без экземпляра: нужен `a.move(...)`, а не `Point.move(...)` |
| `origin` возвращает базовый `Point` у подкласса | Внутри метода класса создание идёт через `cls(...)`, а не через жёстко записанный `Point(...)` |
| После `a + b` изменилась точка `a` | `__add__` должен вернуть новый объект, а не вызывать `move` у левого слагаемого |
| `p.label = ...` у slots молча создаёт поле | В классе нет `__slots__` или поле `label` в него уже внесено |
| Подкласс не видит `move` | `Point3D` объявлен раньше `Point` или перепутан другой класс с тем же именем в ноутбуке |
| Миксин не находит `place` | `place` есть у второго базового класса, а `tagged` вызывает именно `self.place()` |

После занятия слушатель собирает объект с собственными данными и методами, ограничивает набор полей, переиспользует поведение через базовый класс и подмешивает отдельную возможность миксином.
