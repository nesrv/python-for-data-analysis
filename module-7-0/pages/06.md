# 6. XGBoost

Один из самых точных методов для обычных таблиц: не картинок и не видео, а строк и столбцов, как в pandas.

<img src="assets/m7/boost.png" alt="Цикл бустинга: прогноз, ошибка, новое дерево, снова прогноз" style="max-width:100%;height:auto">



Случайный лес из занятия 6.0 и из прошлых разделов строит деревья отдельно друг от друга и усредняет их ответы. Ошибка одного дерева гасится остальными, но следующее дерево не знает, где именно ошиблось предыдущее.

Градиентный бустинг делает иначе. Сначала есть слабый прогноз, часто просто «всем квартирам одну и ту же цену». Потом цикл:

1. Ансамбль выдаёт прогноз по каждой квартире. Это сумма ответов уже построенных деревьев.
2. Считают, где и насколько промахнулись.
3. Новое дерево учат не цене, а этому промаху: оно должно поправить ансамбль в нужную сторону.
4. Дерево добавляют в ансамбль и возвращаются к шагу 1.

Слово «градиентный» про способ выбрать поправку: шаг берут туда, где ошибка убывает быстрее всего. Цикл останавливают, когда заданное число деревьев кончилось или когда проверка перестала улучшаться.

Библиотека этого раздела — XGBoost, extreme gradient boosting. Это быстрая реализация той же идеи. У неё три удобства, которые здесь как раз нужны: она сама принимает пустые `year` и `rooms` (отдельный `SimpleImputer` не обязателен), умеет остановиться раньше времени и считает деревья параллельно. Класс `XGBRegressor` вызывают так же, как лес: `fit`, затем `predict`.

В этом разделе признаки снова только `area`, `year`, `rooms`, то же разбиение 8000/2000 с `random_state=0`. Район не добавляем, чтобы сравнивать бустинг с лесом из 7.0.1, а не с моделью, у которой больше столбцов.

Таблица: [flats_gaps.csv](data/flats_gaps.csv). В ноутбуке путь `module-7-0/data/flats_gaps.csv`.

**Ячейка. Модель с параметрами по умолчанию.**

```python
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.metrics import mean_absolute_error
from xgboost import XGBRegressor

flats = pd.read_csv("module-7-0/data/flats_gaps.csv")

# Те же три числа, что в перекрёстной проверке. Пустые ячейки оставляем:
# XGBoost откладывает их в отдельную ветку дерева и не требует заранее подставить среднее.
X_xgb = flats[["area", "year", "rooms"]]
y_xgb = flats.price
X_train_xgb, X_valid_xgb, y_train_xgb, y_valid_xgb = train_test_split(
    X_xgb, y_xgb, train_size=0.8, test_size=0.2, random_state=0
)

# random_state=0 фиксирует порядок, в котором бустинг перебирает строки.
# В версии 3.4 незаданные n_estimators и learning_rate библиотека заменяет сама:
# 100 деревьев и шаг 0.3.
model_default = XGBRegressor(random_state=0)
model_default.fit(X_train_xgb, y_train_xgb)
pred_default = model_default.predict(X_valid_xgb)
mae_default = mean_absolute_error(y_valid_xgb, pred_default)
print(f"MAE, параметры по умолчанию: {mae_default:.2f}")
```

**Критерий 7.0.5а.** MAE — **323.12**. Это ниже 353.69 у леса из десяти деревьев со средним вместо пропуска: бустинг идёт по ошибкам, а пустые годы не затирает одним числом на всех.

**Ячейка. Сколько деревьев.**

```python
# n_estimators — сколько деревьев поставить в цепочку.
# Мало деревьев: ансамбль не успевает поправить ошибку (недообучение).
# Много деревьев при крупном шаге: цепочка запоминает обучение и на проверке становится хуже.
model_500 = XGBRegressor(n_estimators=500, random_state=0)
model_500.fit(X_train_xgb, y_train_xgb)
pred_500 = model_500.predict(X_valid_xgb)
mae_500 = mean_absolute_error(y_valid_xgb, pred_500)
print(f"MAE, 500 деревьев: {mae_500:.2f}")
```

**Критерий 7.0.5б.** MAE — **360.31**. Пятьсот деревьев со шагом 0.3 на проверке хуже, чем сто. Это переобучение: лишние деревья подгоняют уже мелкий шум обучения.

**Ячейка. Ранняя остановка.**

```python
# n_estimators=500 — верхний предел, а не обязанность дойти до конца.
# early_stopping_rounds=5: если пять новых деревьев подряд не улучшили проверку, стройку останавливают.
# eval_set — та самая проверка, по которой решают «стало лучше или нет».
# verbose=False прячет журнал каждого дерева. Для сверки MAE он не нужен.
model_early = XGBRegressor(n_estimators=500, early_stopping_rounds=5, random_state=0)
model_early.fit(
    X_train_xgb,
    y_train_xgb,
    eval_set=[(X_valid_xgb, y_valid_xgb)],
    verbose=False,
)
pred_early = model_early.predict(X_valid_xgb)
mae_early = mean_absolute_error(y_valid_xgb, pred_early)
# best_iteration считает с нуля: 10 значит, что полезным оказался раунд номер 10.
print("Остановка на раунде:", model_early.best_iteration)
print(f"MAE, ранняя остановка: {mae_early:.2f}")
```

Ранняя остановка смотрит на те же 2000 строк, по которым потом печатают MAE. Число поэтому чуть добрее, чем у модели, которая проверку совсем не видела. Для выбора числа деревьев этого достаточно. Когда число найдено, для боевого прогноза модель учат уже на всех строках с этим числом деревьев и без `eval_set`.

**Критерий 7.0.5в.** Остановка на раунде **10**. MAE — **305.54**. Это лучше и 323.12, и 360.31: цепочку оборвали до того, как лишние деревья испортили проверку.

**Ячейка. Маленький шаг.**

```python
# learning_rate=0.05: каждое дерево двигает общий прогноз слабее, чем шаг 0.3.
# Поэтому деревьев нужно больше, зато каждое меньше перегибает цену.
# Ранняя остановка сама решает, сколько из тысячи реально пригодилось.
model_slow = XGBRegressor(
    n_estimators=1000,
    learning_rate=0.05,
    early_stopping_rounds=5,
    random_state=0,
)
model_slow.fit(
    X_train_xgb,
    y_train_xgb,
    eval_set=[(X_valid_xgb, y_valid_xgb)],
    verbose=False,
)
pred_slow = model_slow.predict(X_valid_xgb)
mae_slow = mean_absolute_error(y_valid_xgb, pred_slow)
print("Остановка на раунде:", model_slow.best_iteration)
print(f"MAE, маленький шаг: {mae_slow:.2f}")
```

**Критерий 7.0.5г.** Остановка на раунде **96**. MAE — **305.00**. Выигрыш относительно шага 0.3 небольшой, на этих квартирах важнее было вовремя остановиться, чем дробить шаг.

**Ячейка. Число ядер.**

```python
# n_jobs=4 — строить деревья на четырёх ядрах процессора.
# Прогноз от этого не меняется. Параметр нужен, когда таблица большая и fit долго ждёт.
model_jobs = XGBRegressor(
    n_estimators=1000,
    learning_rate=0.05,
    n_jobs=4,
    early_stopping_rounds=5,
    random_state=0,
)
model_jobs.fit(
    X_train_xgb,
    y_train_xgb,
    eval_set=[(X_valid_xgb, y_valid_xgb)],
    verbose=False,
)
pred_jobs = model_jobs.predict(X_valid_xgb)
mae_jobs = mean_absolute_error(y_valid_xgb, pred_jobs)
print(f"MAE, четыре ядра: {mae_jobs:.2f}")
```

**Критерий 7.0.5д.** MAE — **305.00**, та же, что без `n_jobs`. Если числа разошлись, в одном из вызовов другой `random_state` или другой `learning_rate`.

Коротко, чем три вызова отличаются:

| Вызов | Деревьев не больше | Шаг | Ядра | Что получилось |
|-------|--------------------|-----|------|----------------|
| По умолчанию | 100 | 0.3 | все, что даст библиотека | MAE 323.12 |
| Много деревьев | 500 | 0.3 | все | MAE 360.31, проверке хуже |
| Ранняя остановка | 500, вышла на раунде 10 | 0.3 | все | MAE 305.54 |
| Маленький шаг | 1000, вышла на раунде 96 | 0.05 | все | MAE 305.00 |
| Четыре ядра | те же 1000 и шаг 0.05 | 0.05 | 4 | MAE 305.00 |
