**Опора:** занятие 6.0 уже считает среднюю абсолютную ошибку (MAE) случайного леса на файле `module-6-0/data/flats.csv`. Там таблица была полной: у каждой квартиры были площадь, год, комнаты и цена. Рабочая папка VS Code — корень курса, иначе путь к файлу не найдётся.

Цена по-прежнему в тысячах рублей. Вопрос занятия простой: какой способ подготовить таблицу, чтобы прогноз ошибался меньше.

Что уже должно быть знакомо из занятия 6.0:

- строка таблицы — одна квартира;
- признаки — то, по чему модель судит о цене;
- цель — столбец `price`, его модель должна угадать;
- обучение — `fit` на строках, где цена известна;
- прогноз — `predict`, число без подглядывания в настоящую цену;
- MAE — на сколько тысяч рублей прогноз в среднем промахнулся. Меньше — лучше.

Новые слова этого занятия:

| Слово | Простыми словами |
|-------|------------------|
| Пропуск, `NaN` | Пустая ячейка. Не ноль: ноль был бы «комнат нет», а `NaN` значит «значение потеряли» |
| Импутация | Вписать число вместо пустой ячейки. Здесь вписываем среднее по столбцу |
| Категория | Текст из короткого списка. Район бывает только «север», «юг», «центр», «запад», «восток» |
| Порядковое кодирование | Заменить каждое слово своим целым числом: «север» → 0, «юг» → 1 и так далее |
| Прямое кодирование | На каждое слово завести отдельный столбец из нулей и единиц |
| Конвейер, `Pipeline` | Несколько шагов в одном объекте. Один `fit` готовит данные и учит модель, один `predict` повторяет подготовку |
| Складка | Одна из пяти равных частей таблицы. По очереди каждая часть играет роль проверки |
| Бустинг | Деревья строят по очереди. Каждое следующее учится на ошибках уже собранных |
| `learning_rate` | Насколько сильно новое дерево двигает общий прогноз. Маленький шаг — меньше риск перегнуть |

## 7.0.1. Три способа закрыть пропуски

Случайный лес из scikit-learn не начинает обучение, если в признаках остался `NaN`. Сообщение будет про `NaN` или `Input contains`. Это не поломка таблицы, а требование библиотеки: ей нужно число в каждой ячейке.

Дальше три способа. Их сравнивают одной и той же проверкой, иначе непонятно, что именно уменьшило ошибку.

1. **Удалить столбцы с пропусками.** Просто, но жадно. Если в столбце из 10000 ячеек пуста одна, пропадает весь столбец, и модель больше не видит год или комнаты.
2. **Подставить среднее.** По столбцу `year` на обучении считают средний год и вписывают его во все пустые годы. Настоящий год квартиры был другим, но столбец остаётся, и у леса есть чем пользоваться.
3. **Среднее плюс флаг.** То же среднее и ещё один столбец, например `year_was_missing`. В нём `True`, если год изначально был пуст. Иногда сам факт пропуска связан с ценой: анкета заполнена не до конца. Флаг даёт модели этот факт отдельно от подставленного числа.

На этом шаге район не берём. Район — текст, лес его тоже не примет, и ошибка смешалась бы с темой следующего раздела. Сравниваем только `area`, `year`, `rooms`.

**Ячейка. Чтение таблицы и разбиение.**

```python
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.ensemble import RandomForestRegressor
from sklearn.metrics import mean_absolute_error
from sklearn.impute import SimpleImputer

# index_col не указываем: первая колонка файла — это flat_id, а не номер строки pandas.
flats = pd.read_csv("module-7-0/data/flats_gaps.csv")
print(flats.shape)
# isna() даёт True в пустых ячейках, sum() считает их по каждому столбцу.
print(flats.isna().sum())

# y — столбец ответов. Модель будет подбирать цену, глядя на остальные поля.
y = flats.price
# Номер квартиры и текст «цена 6230» ничего не объясняют.
# Если оставить price_note, модель прочитает цену из подписи и ошибка станет нулевой.
X = flats.drop(columns=["price", "price_note", "flat_id"])

# 80 % строк — обучение, 20 % — проверка. random_state=0 фиксирует жребий:
# без него у каждого запуска были бы другие 2000 проверочных квартир и другая MAE.
X_train, X_valid, y_train, y_valid = train_test_split(
    X, y, train_size=0.8, test_size=0.2, random_state=0
)
print(X_train.shape, X_valid.shape)

# select_dtypes(include="number") забирает area, year, rooms и оставляет район в стороне.
# copy(), чтобы следующие ячейки не меняли исходный X_train.
num_cols = list(X_train.select_dtypes(include="number").columns)
X_train_num = X_train[num_cols].copy()
X_valid_num = X_valid[num_cols].copy()
print(num_cols)
```

**Критерий 7.0.1а.** `shape` равен `(10000, 7)`. Пропусков: `district` 243, `year` 588, `rooms` 434, у `flat_id`, `area`, `price` и `price_note` нули. После разбиения печать `(8000, 4) (2000, 4)`: четыре столбца — это ещё и район, он в `X`, но не в `num_cols`. Числовые столбцы: `area`, `year`, `rooms`.

Дальше одна и та же функция измеряет все три способа. Так в сравнении меняется только подготовка таблицы, а не число деревьев.

**Ячейка. Удаление столбцов.**

```python
def score_dataset(X_train, X_valid, y_train, y_valid):
    # n_estimators=10 — десять деревьев в лесу. Для сверки числа важнее, чем для качества:
    # с другим числом деревьев MAE будет другой, и критерий ниже не сойдётся.
    model = RandomForestRegressor(n_estimators=10, random_state=0)
    # fit видит только обучение. Цены проверки в обучение не попадают.
    model.fit(X_train, y_train)
    preds = model.predict(X_valid)
    # mean_absolute_error усредняет |прогноз − настоящая цена| по 2000 строкам проверки.
    return mean_absolute_error(y_valid, preds)

# Список имён столбцов, где на обучении есть хотя бы одна пустая ячейка.
# Проверку тут не смотрим: набор выбрасываемых столбцов решают по обучению,
# а из проверки выкидывают те же имена. Иначе у двух таблиц разный набор колонок.
cols_with_missing = [col for col in X_train_num.columns if X_train_num[col].isna().any()]
print(cols_with_missing)
print(X_train_num.isna().sum())

reduced_X_train = X_train_num.drop(columns=cols_with_missing)
reduced_X_valid = X_valid_num.drop(columns=cols_with_missing)
mae_drop = score_dataset(reduced_X_train, reduced_X_valid, y_train, y_valid)
# :.2f печатает ровно два знака после запятой, чтобы 278.10 не превращалось в 278.1.
print(f"MAE, удаление столбцов: {mae_drop:.2f}")
```

**Критерий 7.0.1б.** В списке пропусков `year` и `rooms`. Площадь в список не входит: она заполнена у всех. На обучении пустых лет 457, пустых комнат 346. Это меньше 588 и 434, потому что часть дыр уехала в проверку. MAE удаления столбцов — **389.39**. В модели осталась одна площадь, поэтому промах большой: по площади цены квартир одного метража всё равно различаются.

**Ячейка. Среднее и среднее с флагом.**

```python
# SimpleImputer() без аргументов подставляет среднее.
# fit_transform считает среднее по X_train_num и сразу заполняет эту таблицу.
# transform на проверке подставляет уже посчитанные средние, заново их не ищет.
# Если вызвать fit и на проверке, среднее будет «подсмотрено» у квартир, которых модель не должна знать.
imputer = SimpleImputer()
imputed_X_train = pd.DataFrame(imputer.fit_transform(X_train_num), columns=num_cols)
imputed_X_valid = pd.DataFrame(imputer.transform(X_valid_num), columns=num_cols)
mae_mean = score_dataset(imputed_X_train, imputed_X_valid, y_train, y_valid)
print(f"MAE, среднее: {mae_mean:.2f}")

# copy(), потому что дальше добавляем столбцы. Исходный X_train_num пригодится, если ячейку перезапустят.
X_train_plus = X_train_num.copy()
X_valid_plus = X_valid_num.copy()
for col in cols_with_missing:
    # isna() ещё до заполнения: после среднего пустых ячеек уже не останется и флаг станет бесполезным.
    X_train_plus[col + "_was_missing"] = X_train_plus[col].isna()
    X_valid_plus[col + "_was_missing"] = X_valid_plus[col].isna()

imputer_plus = SimpleImputer()
imputed_X_train_plus = pd.DataFrame(imputer_plus.fit_transform(X_train_plus), columns=X_train_plus.columns)
imputed_X_valid_plus = pd.DataFrame(imputer_plus.transform(X_valid_plus), columns=X_valid_plus.columns)
mae_flags = score_dataset(imputed_X_train_plus, imputed_X_valid_plus, y_train, y_valid)
print(f"MAE, среднее и флаги: {mae_flags:.2f}")
print(list(imputed_X_train_plus.columns))
```

`fit_transform` возвращает массив без имён столбцов. Обратно в `DataFrame` имена кладут вручную, иначе следующая ячейка не отличит год от комнат.

**Критерий 7.0.1в.** MAE среднего — **353.69**. MAE среднего с флагами — **352.63**. Оба числа меньше 389.39: год и комнаты полезнее, чем их выбрасывание. Флаги почти ничего не меняют, на этой таблице пропуск года не несёт отдельной подсказки о цене. Столбцы после флагов: `area`, `year`, `rooms`, `year_was_missing`, `rooms_was_missing`.

Вывод раздела: из трёх способов на этих квартирах лучше среднее. Флаги можно оставить, они не вредят, но и не обязательны. Удалять `year` и `rooms` не стоит.

## 7.0.2. Район как категория

`district` — не число. Значения: север, юг, центр, запад, восток. Между ними нет шкалы «центр больше запада на единицу». Если просто заменить слова числами 0, 1, 2, линейная модель решит, что разница между соседними кодами одинакова. Дерево и лес так не считают: они режут «код района равен такому-то», поэтому порядковые числа им не вредят. Всё равно полезно увидеть оба способа.

Три варианта, снова на одной и той же проверке:

1. **Выбросить район.** Останется площадь. Это нижняя планка: так мы узнаем, сколько даёт сам текст района.
2. **Порядковое кодирование, `OrdinalEncoder`.** Каждому району — свое целое. Соответствие выбирает библиотека по алфавиту, не мы. Для леса этого достаточно.
3. **Прямое кодирование, `OneHotEncoder`.** Появляется столбец `district_центр`: 1, если квартира в центре, и 0 иначе. То же для остальных районов. Никакого ложного порядка нет. Способ раздувает таблицу, если разных слов сотни. Здесь слов мало, меньше пятнадцати, поэтому он уместен.

Пустой район записываем словом `нет`. Для кодировщика `NaN` — не категория, а снова пропуск, и `OrdinalEncoder` остановится. Слово `нет` честно говорит: район неизвестен, это шестая категория, а не «ноль комнат».

Год и комнаты на этом шаге снова выбрасываем. Их пользу уже измерили. Если оставить их здесь, MAE района смешается с MAE заполнения.

**Ячейка. Подготовка текста и модель без района.**

```python
from sklearn.preprocessing import OrdinalEncoder, OneHotEncoder

# cols_with_missing — это year и rooms из прошлого раздела.
# После drop остаются area и district.
X_train_cat = X_train.drop(columns=cols_with_missing).copy()
X_valid_cat = X_valid.drop(columns=cols_with_missing).copy()
# Одно и то же слово в обеих таблицах, иначе у проверки появится категория, которой не было в обучении.
X_train_cat["district"] = X_train_cat["district"].fillna("нет")
X_valid_cat["district"] = X_valid_cat["district"].fillna("нет")
object_cols = ["district"]

def score_forest(X_train, X_valid, y_train, y_valid):
    # Деревьев больше, чем в 7.0.1: 30 вместо 10. Числа MAE этого раздела с прошлым не складывают.
    model = RandomForestRegressor(n_estimators=30, random_state=0)
    model.fit(X_train, y_train)
    return mean_absolute_error(y_valid, model.predict(X_valid))

# include="number" отбрасывает district. В таблице остаётся одна площадь.
drop_X_train = X_train_cat.select_dtypes(include="number")
drop_X_valid = X_valid_cat.select_dtypes(include="number")
mae_no_district = score_forest(drop_X_train, drop_X_valid, y_train, y_valid)
print(f"MAE без района: {mae_no_district:.2f}")
```

**Ячейка. Порядковые числа.**

```python
label_X_train = X_train_cat.copy()
label_X_valid = X_valid_cat.copy()
ordinal_encoder = OrdinalEncoder()
# fit_transform запоминает список районов на обучении и подставляет числа.
# transform на проверке пользуется тем же списком, а не строит новый.
label_X_train[object_cols] = ordinal_encoder.fit_transform(X_train_cat[object_cols])
label_X_valid[object_cols] = ordinal_encoder.transform(X_valid_cat[object_cols])
# categories_ показывает, какое слово стало нулём, какое единицей. Это алфавит, не «лучше / хуже».
print(ordinal_encoder.categories_)
print(label_X_train[["area", "district"]].head())
mae_ordinal = score_forest(label_X_train, label_X_valid, y_train, y_valid)
print(f"MAE, порядковый код: {mae_ordinal:.2f}")
```

**Ячейка. Столбец на каждый район.**

```python
# handle_unknown="ignore": если на проверке вдруг будет район, которого не было в обучении,
# строка получит нули во всех столбцах района, а не ошибку.
# sparse_output=False: обычный массив, а не сжатая матрица. Из него сразу собирается таблица.
oh_encoder = OneHotEncoder(handle_unknown="ignore", sparse_output=False)
oh_train = pd.DataFrame(
    oh_encoder.fit_transform(X_train_cat[object_cols]),
    # Имена вида district_центр, а не 0, 1, 2. Иначе по печати не понять, где центр.
    columns=oh_encoder.get_feature_names_out(object_cols),
    # index совпадает с X_train_cat, иначе concat ниже склеит строки не тех квартир.
    index=X_train_cat.index,
)
oh_valid = pd.DataFrame(
    oh_encoder.transform(X_valid_cat[object_cols]),
    columns=oh_encoder.get_feature_names_out(object_cols),
    index=X_valid_cat.index,
)
# Числовую площадь ставим рядом с новыми столбцами. Сам текст district больше не нужен.
oh_X_train = pd.concat([X_train_cat.select_dtypes(include="number"), oh_train], axis=1)
oh_X_valid = pd.concat([X_valid_cat.select_dtypes(include="number"), oh_valid], axis=1)
print(list(oh_train.columns))
print(oh_X_train.head(3))
mae_onehot = score_forest(oh_X_train, oh_X_valid, y_train, y_valid)
print(f"MAE, прямое кодирование: {mae_onehot:.2f}")
```

В трёх первых строках `head` в каждой строке ровно одна единица среди столбцов района: квартира не может быть сразу в двух районах. У слова `нет` единица стоит в `district_нет`.

**Критерий 7.0.2.** MAE без района — **389.37**. Порядковый код — **278.24**. Прямое кодирование — **278.10**. Столбцы прямого кода: `district_восток`, `district_запад`, `district_нет`, `district_север`, `district_центр`, `district_юг`. Худший вариант — выбросить район: ошибка падает примерно на 110, как только район возвращается. Два кодирования на лесе почти совпали. Лес не требует, чтобы числа районов шли «по возрастанию качества». Для линейной модели в следующем курсе безопаснее прямое кодирование.

## 7.0.3. Конвейер

В прошлых ячейках легко ошибиться руками:

- посчитать среднее по проверке, а не по обучению;
- заполнить пропуски уже после того, как построили флаг;
- забыть закодировать район перед `predict`;
- выбросить год, хотя его можно было заполнить.

Конвейер собирает подготовку и лес в один объект. `ColumnTransformer` ведёт числа и текст разными ветками, потому что среднее по слову «центр» бессмысленно, а столбец из нулей и единиц для площади не нужен.

Что делает каждая ветка:

- числа `area`, `year`, `rooms` — `SimpleImputer(strategy="constant")`. Пустую ячейку заменяют константой. Без `fill_value` константа равна 0;
- район — сначала самый частый район вместо пустого текста (`most_frequent`), затем прямое кодирование.

В `predict` передают сырую проверку, с пустыми ячейками и словами. Конвейер сам повторяет шаги, которые запомнил на `fit`. Отдельный `imputer.transform` здесь писать не нужно.

**Ячейка:**

```python
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline

numerical_cols = ["area", "year", "rooms"]
categorical_cols = ["district"]

# strategy="constant" пишет в пустую ячейку одно и то же число, по умолчанию 0.
# Это другой способ, не среднее из раздела 7.0.1. Его и сравниваем отдельной MAE.
numerical_transformer = SimpleImputer(strategy="constant")
# Внутренний Pipeline: сначала закрыть пустой район, потом превратить слово в столбцы 0/1.
# OneHotEncoder не принимает NaN, поэтому imputer стоит раньше onehot.
categorical_transformer = Pipeline(
    steps=[
        ("imputer", SimpleImputer(strategy="most_frequent")),
        ("onehot", OneHotEncoder(handle_unknown="ignore")),
    ]
)
# ColumnTransformer применяет num только к трём числам, cat только к district.
# Остальные столбцы X_train (их нет в этих списках) в модель не попадут.
preprocessor = ColumnTransformer(
    transformers=[
        ("num", numerical_transformer, numerical_cols),
        ("cat", categorical_transformer, categorical_cols),
    ]
)
model = RandomForestRegressor(n_estimators=30, random_state=0)
# Порядок в steps важен: сначала preprocessor, потом model.
# Наоборот нельзя: лес не умеет читать пустые ячейки и слово «центр».
my_pipeline = Pipeline(steps=[("preprocessor", preprocessor), ("model", model)])

# fit на сыром X_train: внутри и заполнение, и кодирование, и обучение леса.
my_pipeline.fit(X_train, y_train)
# predict тоже на сыром X_valid. Подготовка проверки идёт теми правилами, что выучены на обучении.
preds = my_pipeline.predict(X_valid)
mae_pipeline = mean_absolute_error(y_valid, preds)
print(f"MAE конвейера: {mae_pipeline:.2f}")
```

**Критерий 7.0.3.** MAE конвейера — **129.81**. Она заметно ниже 278 из прошлого раздела. Причина не в «магии конвейера», а в составе признаков: год и комнаты больше не выбрасываются, район тоже остаётся. Конвейер только не даёт перепутать порядок шагов.

## 7.0.4. Перекрёстная проверка

До сих пор проверка была одним жребием: 2000 строк при `random_state=0`. Другой жребий дал бы другую MAE. Если разница двух моделей маленькая, можно выбрать ту, которой просто повезло с этими двумя тысячами.

Перекрёстная проверка делит все 10000 строк на 5 равных частей, их называют складками. Опыт повторяют пять раз. Каждый раз одна складка — проверка, остальные четыре — обучение. Каждая квартира ровно один раз попадает в проверку. Итог — пять MAE и их среднее.

Схема для пяти складок:

| Опыт | Обучение | Проверка |
|------|----------|----------|
| 1 | складки 2–5 | складка 1 |
| 2 | складки 1, 3–5 | складка 2 |
| 3 | складки 1, 2, 4, 5 | складка 3 |
| 4 | складки 1–3 и 5 | складка 4 |
| 5 | складки 1–4 | складка 5 |

Цена точности — пять обучений вместо одного. На 10000 строк это ещё секунды. Когда одно обучение идёт десятки минут, оставляют одно отложенное разбиение, как в занятии 6.0.

Здесь признаки только `area`, `year`, `rooms`. Тогда среднее по складкам можно сравнивать с импутацией из 7.0.1, а не с моделью, которая дополнительно видит район. Конвейер с `SimpleImputer` нужен обязательно: внутри каждой складки среднее должно считаться заново, только по её четырём обучающим частям. Если заполнить пропуски один раз до цикла, в среднее попадёт и та складка, которая сейчас считается проверкой.

**Ячейка:**

```python
from sklearn.model_selection import cross_val_score

cols_to_use = ["area", "year", "rooms"]
X_cv = flats[cols_to_use]
y_cv = flats.price

cv_pipeline = Pipeline(
    steps=[
        # Пустые года и комнаты. Среднее этот шаг пересчитает на каждой складке отдельно.
        ("preprocessor", SimpleImputer()),
        ("model", RandomForestRegressor(n_estimators=20, random_state=0)),
    ]
)
# cv=5 — пять складок.
# scoring="neg_mean_absolute_error": в sklearn все меры устроены так, что большее число лучше.
# Обычная MAE устроена наоборот, поэтому библиотека отдаёт её со знаком минус.
# Умножение на -1 возвращает привычную ошибку «на сколько промахнулись».
scores = -1 * cross_val_score(
    cv_pipeline, X_cv, y_cv, cv=5, scoring="neg_mean_absolute_error"
)
print("MAE по складкам:", [f"{float(s):.2f}" for s in scores])
print(f"Средняя MAE: {float(scores.mean()):.2f}")
```

**Критерий 7.0.4.** Пять чисел: **339.98, 341.94, 344.85, 346.53, 330.90**. Среднее — **340.84**. Самая удачная складка и самая неудачная отличаются примерно на 16. Это меньше, чем выигрыш от района в разделе 7.0.2 (около 110) и меньше, чем выигрыш конвейера, который оставил и год, и район. Вывод «район полезен» от одного жребия не зависит.

Отдельные `X_train` и `X_valid` в этой ячейке не создают. `cross_val_score` делит таблицу сам.

## 7.0.5. Градиентный бустинг и XGBoost

Случайный лес из занятия 6.0 и из прошлых разделов строит деревья отдельно друг от друга и усредняет их ответы. Ошибка одного дерева гасится остальными, но следующее дерево не знает, где именно ошиблось предыдущее.

Градиентный бустинг делает иначе. Сначала есть слабый прогноз, часто просто «всем квартирам одну и ту же цену». Потом цикл:

1. Ансамбль выдаёт прогноз по каждой квартире. Это сумма ответов уже построенных деревьев.
2. Считают, где и насколько промахнулись.
3. Новое дерево учат не цене, а этому промаху: оно должно поправить ансамбль в нужную сторону.
4. Дерево добавляют в ансамбль и возвращаются к шагу 1.

Слово «градиентный» про способ выбрать поправку: шаг берут туда, где ошибка убывает быстрее всего. Цикл останавливают, когда заданное число деревьев кончилось или когда проверка перестала улучшаться.

Библиотека этого раздела — XGBoost, extreme gradient boosting. Это быстрая реализация той же идеи. У неё три удобства, которые здесь как раз нужны: она сама принимает пустые `year` и `rooms` (отдельный `SimpleImputer` не обязателен), умеет остановиться раньше времени и считает деревья параллельно. Класс `XGBRegressor` вызывают так же, как лес: `fit`, затем `predict`.

В этом разделе признаки снова только `area`, `year`, `rooms`, то же разбиение 8000/2000 с `random_state=0`. Район не добавляем, чтобы сравнивать бустинг с лесом из 7.0.1, а не с моделью, у которой больше столбцов.

**Ячейка. Модель с параметрами по умолчанию.**

```python
from xgboost import XGBRegressor

# Те же три числа, что в перекрёстной проверке. Пустые ячейки оставляем:
# XGBoost откладывает их в отдельную ветку дерева и не требует заранее подставить среднее.
X_xgb = flats[["area", "year", "rooms"]]
y_xgb = flats.price
X_train_xgb, X_valid_xgb, y_train_xgb, y_valid_xgb = train_test_split(
    X_xgb, y_xgb, train_size=0.8, test_size=0.2, random_state=0
)

# random_state=0 фиксирует порядок, в котором бустинг перебирает строки.
# В версии 3.4 незаданные n_estimators и learning_rate библиотека заменяет сама:
# 100 деревьев и шаг 0.3.
model_default = XGBRegressor(random_state=0)
model_default.fit(X_train_xgb, y_train_xgb)
pred_default = model_default.predict(X_valid_xgb)
mae_default = mean_absolute_error(y_valid_xgb, pred_default)
print(f"MAE, параметры по умолчанию: {mae_default:.2f}")
```

**Критерий 7.0.5а.** MAE — **323.12**. Это ниже 353.69 у леса из десяти деревьев со средним вместо пропуска: бустинг идёт по ошибкам, а пустые годы не затирает одним числом на всех.

**Ячейка. Сколько деревьев.**

```python
# n_estimators — сколько деревьев поставить в цепочку.
# Мало деревьев: ансамбль не успевает поправить ошибку (недообучение).
# Много деревьев при крупном шаге: цепочка запоминает обучение и на проверке становится хуже.
model_500 = XGBRegressor(n_estimators=500, random_state=0)
model_500.fit(X_train_xgb, y_train_xgb)
pred_500 = model_500.predict(X_valid_xgb)
mae_500 = mean_absolute_error(y_valid_xgb, pred_500)
print(f"MAE, 500 деревьев: {mae_500:.2f}")
```

**Критерий 7.0.5б.** MAE — **360.31**. Пятьсот деревьев со шагом 0.3 на проверке хуже, чем сто. Это переобучение: лишние деревья подгоняют уже мелкий шум обучения.

**Ячейка. Ранняя остановка.**

```python
# n_estimators=500 — верхний предел, а не обязанность дойти до конца.
# early_stopping_rounds=5: если пять новых деревьев подряд не улучшили проверку, стройку останавливают.
# eval_set — та самая проверка, по которой решают «стало лучше или нет».
# verbose=False прячет журнал каждого дерева. Для сверки MAE он не нужен.
model_early = XGBRegressor(n_estimators=500, early_stopping_rounds=5, random_state=0)
model_early.fit(
    X_train_xgb,
    y_train_xgb,
    eval_set=[(X_valid_xgb, y_valid_xgb)],
    verbose=False,
)
pred_early = model_early.predict(X_valid_xgb)
mae_early = mean_absolute_error(y_valid_xgb, pred_early)
# best_iteration считает с нуля: 10 значит, что полезным оказался раунд номер 10.
print("Остановка на раунде:", model_early.best_iteration)
print(f"MAE, ранняя остановка: {mae_early:.2f}")
```

Ранняя остановка смотрит на те же 2000 строк, по которым потом печатают MAE. Число поэтому чуть добрее, чем у модели, которая проверку совсем не видела. Для выбора числа деревьев этого достаточно. Когда число найдено, для боевого прогноза модель учат уже на всех строках с этим числом деревьев и без `eval_set`.

**Критерий 7.0.5в.** Остановка на раунде **10**. MAE — **305.54**. Это лучше и 323.12, и 360.31: цепочку оборвали до того, как лишние деревья испортили проверку.

**Ячейка. Маленький шаг.**

```python
# learning_rate=0.05: каждое дерево двигает общий прогноз слабее, чем шаг 0.3.
# Поэтому деревьев нужно больше, зато каждое меньше перегибает цену.
# Ранняя остановка сама решает, сколько из тысячи реально пригодилось.
model_slow = XGBRegressor(
    n_estimators=1000,
    learning_rate=0.05,
    early_stopping_rounds=5,
    random_state=0,
)
model_slow.fit(
    X_train_xgb,
    y_train_xgb,
    eval_set=[(X_valid_xgb, y_valid_xgb)],
    verbose=False,
)
pred_slow = model_slow.predict(X_valid_xgb)
mae_slow = mean_absolute_error(y_valid_xgb, pred_slow)
print("Остановка на раунде:", model_slow.best_iteration)
print(f"MAE, маленький шаг: {mae_slow:.2f}")
```

**Критерий 7.0.5г.** Остановка на раунде **96**. MAE — **305.00**. Выигрыш относительно шага 0.3 небольшой, на этих квартирах важнее было вовремя остановиться, чем дробить шаг.

**Ячейка. Число ядер.**

```python
# n_jobs=4 — строить деревья на четырёх ядрах процессора.
# Прогноз от этого не меняется. Параметр нужен, когда таблица большая и fit долго ждёт.
model_jobs = XGBRegressor(
    n_estimators=1000,
    learning_rate=0.05,
    n_jobs=4,
    early_stopping_rounds=5,
    random_state=0,
)
model_jobs.fit(
    X_train_xgb,
    y_train_xgb,
    eval_set=[(X_valid_xgb, y_valid_xgb)],
    verbose=False,
)
pred_jobs = model_jobs.predict(X_valid_xgb)
mae_jobs = mean_absolute_error(y_valid_xgb, pred_jobs)
print(f"MAE, четыре ядра: {mae_jobs:.2f}")
```

**Критерий 7.0.5д.** MAE — **305.00**, та же, что без `n_jobs`. Если числа разошлись, в одном из вызовов другой `random_state` или другой `learning_rate`.

Коротко, чем три вызова отличаются:

| Вызов | Деревьев не больше | Шаг | Ядра | Что получилось |
|-------|--------------------|-----|------|----------------|
| По умолчанию | 100 | 0.3 | все, что даст библиотека | MAE 323.12 |
| Много деревьев | 500 | 0.3 | все | MAE 360.31, проверке хуже |
| Ранняя остановка | 500, вышла на раунде 10 | 0.3 | все | MAE 305.54 |
| Маленький шаг | 1000, вышла на раунде 96 | 0.05 | все | MAE 305.00 |
| Четыре ядра | те же 1000 и шаг 0.05 | 0.05 | 4 | MAE 305.00 |

## 7.0.6. Самопроверка

Пройдите список после того, как все ячейки отработали сверху вниз.

1. В `flats_gaps.csv` 10000 строк и 7 столбцов, пустых цен нет.
2. Обучение — 8000 строк, проверка — 2000, `random_state=0`.
3. Удаление `year` и `rooms` даёт MAE 389.39, среднее — 353.69, среднее с флагами — 352.63.
4. Без района MAE 389.37, с порядковым кодом 278.24, с прямым кодированием 278.10.
5. Конвейер на сырых `X_train` и `X_valid` даёт MAE 129.81.
6. Пять складок дают среднюю MAE 340.84.
7. XGBoost на `area`, `year`, `rooms`: по умолчанию 323.12, пятьсот деревьев 360.31, ранняя остановка на раунде 10 даёт 305.54, маленький шаг останавливается на раунде 96 и даёт 305.00. Четыре ядра эту ошибку не меняют.

| Симптом | Что проверить |
|---------|----------------|
| `ValueError` про `NaN` | В `fit` ушли `year` или `rooms` без `SimpleImputer` |
| MAE удаления не 389.39 | Другое `random_state`, другое `n_estimators` или в таблицу попал `district` |
| `OrdinalEncoder` падает на пустом районе | Перед кодированием `fillna("нет")` и в обучении, и в проверке |
| В прямом коде нет `district_центр` | Имена берут из `get_feature_names_out`, а не оставляют номера 0, 1, 2 |
| Строки после `concat` съехали | У таблиц прямого кода тот же `index`, что у `X_train_cat` |
| MAE конвейера около 350, а не 129.81 | В `ColumnTransformer` не передан `district` |
| Среднее по складкам отрицательное | Перед печатью результат `cross_val_score` умножают на `-1` |
| `FileNotFoundError` | Путь `module-7-0/data/flats_gaps.csv`, ноутбук запущен из корня курса |
| `No module named sklearn` | Ядро ноутбука — `.venv`, пакет ставили при активном `(.venv)` |
| `No module named xgboost` | В том же `.venv` выполнили `python -m pip install xgboost` |
| MAE пятисот деревьев лучше, чем у ста | В `XGBRegressor` не передали `n_estimators=500` или другой `random_state` |
| Ранняя остановка доходит до 500 | В `fit` нет `eval_set` с проверочными строками |

После занятия слушатель по одной и той же проверке выбирает подготовку: пустые числа закрывает средним, район не выбрасывает, повторяемые шаги собирает в конвейер, устойчивость оценки смотрит по пяти складкам, а число деревьев бустинга ограничивает ранней остановкой, а не круглым «чем больше, тем лучше».
